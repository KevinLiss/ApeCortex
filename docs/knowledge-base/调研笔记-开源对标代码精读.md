## 二、逐仓精读要点

### 1. mem0（记忆系统对标 → 需求1）

**核心修正**：网上广为流传的"extract + update 两次 LLM、ADD/UPDATE/DELETE/NONE 四路决策"管线**已被官方退役**。现行 V3 管线（`mem0/memory/main.py:920-1207`）：

- **单次 LLM 调用做 ADD-only 提取**（`ADDITIVE_EXTRACTION_PROMPT`，main.py:944；`response_format=json_object`）。`DEFAULT_UPDATE_MEMORY_PROMPT` 在 configs/prompts.py:176 定义但生产代码零引用（仅测试用）——官方用行动承认"LLM 返回 ID 做更新/删除"路线脆弱
- 管线：取本 session 最近 10 条消息 → 检索 top10 旧记忆（UUID→整数映射防编造 ID，main.py:936-940）→ 单次 LLM 提取 → 批量 embed → **MD5 hash 双重去重**（库内+批内）→ 批量 insert 失败逐条降级 → 写 history 审计表 → **非 LLM 实体抽取**链接到独立 entity collection
- 实体图已从"LLM 图谱"退化为轻量实体库（vector store 第二 collection + `linked_memory_ids`），`graph_memory.py` 已删除
- 坑：SQLite 全局 `threading.Lock`（storage.py:15）在多 worker 下踩锁；`AsyncMemory` 只是 `asyncio.to_thread` 包同步（main.py:2644），非真异步——聊天沉淀必须做成后台任务
- 最小可用组合：OpenAI 兼容 LLM + openai embedder + 本地嵌入式 Qdrant + SQLite，核心依赖仅 8 个

### 2. gpt-researcher（深度调研对标 → 需求2）

- 一次常规调研 **4-6 次 LLM 调用**：选 agent(1) → 子查询规划(1) → 报告(1) + 可选 curate(1)，中间检索/压缩零 LLM
- 上下文压缩默认走 **keyword/BM25 零 LLM** 路径（`context/select.py:53`，`KEYWORD_MAX_RESULTS=25`），<8000 字符快路径直通
- retriever 契约极薄：`BaseRetriever.search(max_results)->List[dict]` + `requires_scraping` 属性；custom 实现仅 ~80 行
- **防御代码比 scraper 本身值钱**：SSRF 校验、反爬页面/词表/PDF 二进制启发式过滤（scraper.py:41-113）、`visited_urls` 去重、引用确定性排序（actions/markdown_processing.py:105-121）
- 护栏默认值：`MAX_SEARCH_RESULTS_PER_QUERY=5`、`MAX_SCRAPER_WORKERS=15`（Semaphore）、fast/smart/strategic token 上限 6000/12000/8000、MCP 超时 300s；**主流程无总调用次数硬护栏**（MAX_ITERATIONS 仅声明未使用）→ 自研必须补
- `mcp-server/` 目录**已迁出**为独立仓库 assafelovic/gptr-mcp，只剩 README——工具面是粗粒度（deep_research 一次跑全程），不是原子 search/scrape 工具
- 坑：langchain 七件套+langgraph 五件套是**硬依赖**（pyproject.toml:77-88），压缩路径直接 import langchain——轻量自研需自写 ~50 行 BM25+截断替代

### 3. storm / stanford-oval（维基式成文对标 → 需求2）

- 引擎实际在 `knowledge_storm/storm_wiki/engine.py`（资料里说的 pipeline.py 已不存在——二手资料过时的又一例证）
- 五阶段：视角发现(2 次) → 多视角对话(**≈36 次**：personas×turns×3) → 大纲(2 次) → 分节成文(每章 1 次，5-8 次) → 润色(1-2 次)。**默认全文 45-50 次 LLM 调用**，贵
- **最有价值的资产是引用整合管线**（storm_dataclass.py:174-412）：逐节 `[n]` 行内引用 → 按 URL 统一编号（同 URL 合并 snippets）→ 删超界引用 → 按全文出现顺序重排。纯 Python 无 LLM，可整体移植——这是防幻觉引用的核心机制
- dspy 依赖实际很薄：只用了 `Predict`/`ChainOfThought`（单次调用+字段切分），未用 optimizer/compile，完全可用 OpenAI 兼容 API 重写 prompt 绕开
- 最重依赖是 sentence-transformers→torch（~523MB wheel）做分节检索，可换 embedding API 归零
- 内置 arXiv 检索器（rm.py:340 StanfordOvalArxivRM）标注 "[Alpha] internal use only" 需内部 endpoint，**不可直接用**；且在 Wikipedia 质量语境下 arXiv 被列为不可靠源（retriever.py:21,97-100）
- 断点续跑设计好：do_research/do_generate_outline/do_generate_article/do_polish_article 四段独立、中间产物落盘——直接映射任务队列幂等重试

### 4. graphiti（时序图谱记忆 → 需求1 的进阶形态）

- **双时序模型**（edges.py:228-259）：`valid_at/invalid_at`（事实有效轴）+ `created_at/expired_at`（系统事务轴），旧事实不删只打标——对"用户偏好随时间演化、旧习惯失效"是精准解法
- add_episode 管线：**单事件 ≥4 次 LLM + 每边 1 次**（实体抽取→embedding 去重(cosine≥0.6)+LLM 裁决→边抽取→矛盾检测）——高频聊天沉淀下成本不可接受
- 值得抄的自研最小版（~600 行可移植）：四时间字段 + 时间语义 prompt 规则（extract_edges.py:182-286）+ `temporal_edge_utils.py` 全 96 行 + `resolve_edge_contradictions` 纯函数 + embedding 去重阈值 0.6 → 落 SQLite facts 表（带 group_id/valid_at/invalid_at + FTS5/向量列）
- 多租户靠 `group_id` 分区（nodes.py:101），查询强制过滤——ApeAdmin 可直接借这个模型（tenant_id=group_id）

### 5. crawl4ai（联网采集 → 需求3）

- Apache-2.0 下**最值得抄的独立代码**（闭包干净、无 playwright 依赖）：`markdown_generation_strategy.py`+`html2text/`（Markdown 生成）、`content_filter_strategy.py`（BM25 滤噪）/`content_filter_strategy_lxml.py`、`chunking_strategy.py`、`deep_crawling/filters.py`（FilterChain+URLPattern/Domain 过滤器）
- 库自带非浏览器路径 `AsyncHTTPCrawlerStrategy`（aiohttp，async_crawler_strategy.py:2521）；注意直接 `import crawl4ai` 会在 `__init__.py` 链上顶层拉 playwright
- 代理：ProxyConfig 支持 socks5、per-request 轮换（proxy_strategy.py RoundRobinProxyStrategy）——对 ApeAdmin 用户环境（Clash `::1:7890` 非法格式代理）是现成参考
- robots.txt 默认关闭（check_robots_txt=True 才检查）；限流仅批模式 RateLimiter；`egress_policy.py` 是进程级出网钩子（Docker 场景防 SSRF）

### 6. trafilatura（静态页抽取 → 需求3 兜底）

- 纯 lxml 四级瀑布（core.py:167-282）：手写 xpaths 规则表(518 行) → readability/justext 对比 → baseline 兜底（含 JSON-LD）→ recall 重试
- Markdown 输出结构保真度高（GFM 表格/代码块/标题，xml.py:654-703），但带 YAML front matter 头需入库前剥离；核心依赖仅 6 个，极轻
- 自带 spider（focused_crawler）**不是通用爬虫**：单站聚焦、同站 5s 限速、仅 blacklist 无白名单
- 并发下载是**线程池非 async**；SSRF 防护默认开——结论：统一 httpx 拉页，trafilatura 只当纯函数 `extract(html)` 用，避免双 HTTP 栈

### 7/8. arxiv.py + pyalex（学术 API → 需求3 专业论文）

- arxiv.py（MIT）：Search→惰性生成器分页（page_size 默认 100、上限 2000）；**内置 3 秒/请求官方限速**（Client.delay_seconds=3.0）且是实例级计时——插件内必须全局单例，否则多实例并发各自计时不共享被限流；无内置 PDF 下载（只有 pdf_url 属性，需自写 httpx）；字段含摘要/作者/分类/DOI；Atom 解析防 XXE
- pyalex（MIT，J535D165/pyalex）：Works/Authors/Institutions 等链式查询 + 游标分页（n_max=10000）；**礼貌池必须设 `config.email`** 否则共享池被限流（约 10 万条/日档）；**默认 max_retries=0，429 直接炸**，需手动调到 ≥3；基于同步 requests——FastAPI 里必须包线程池
- 两者直接当 `collect.arxiv` / `collect.openalex` MCP 工具实现层：各约 20-30 行包装即可

## 四、修正后的 ApeAdmin 知识库插件技术决策（结论）

1. **采集层默认栈**：httpx 拉页（显式代理配置+`trust_env=False`）+ trafilatura 纯函数抽取 + 剥离 YAML front matter；crawl4ai 作为**可选增强插件**（用户要 JS 渲染时装 playwright 再启用），或 vendor 其 Markdown 生成/内容过滤/chunking 四个纯算法模块（Apache-2.0 允许）
2. **记忆层**（用户习惯画像）：mem0 式单次 ADD-only 提取 + MD5 去重 + `linked_memory_ids` 实体链接，外加 graphiti 式四时间字段的 SQLite facts 表（valid_at/invalid_at/expired_at + group_id=租户）；沉淀一律走后台任务队列，绝不阻塞聊天请求
3. **调研层**：STORM 骨架裁剪版（视角→大纲→分节→引用整合管线整体移植）+ gpt-researcher 的 visited_urls/SSRF 防御/WorkerPool 限流 + per-step 成本台账；产出进草稿态人工确认后才入 wiki 层
4. **MCP 工具面**：粗粒度工具（gptr-mcp 式：deep_research/quick_search/write_report），配总 LLM 调用护栏（参照 Spring 版 ≤30 次的既有设计）
5. **学术检索**：`collect.arxiv`（全局单例 Client+3s 节流后台跑）+ `collect.openalex`（config.email 礼貌池 + max_retries≥3 + 线程池包装）
6. **依赖纪律**：禁 langchain/langgraph/dspy/sentence-transformers/torch 五件套进核心依赖；全部用 OpenAI 兼容 API + ~50 行 BM25 自实现替代

## 二、本批三大发现

### 发现 1：WeKnora 是被清单低估的最大金矿（MIT + 完整工程化 LLM Wiki）
38k star 腾讯项目，`internal/application/service/wiki_ingest.go` 是完整 Map/Reduce 编译管线，**配套 50+ 个测试文件**（cancellation/stress/durability/guard 全覆盖）：
- 摄入队列：`task_pending_ops` 持久化（task_type=wiki:ingest，30s debounce，批 5 文档）
- Map 相：Pass 0 候选 slug 提取 → WikiKnowledgeExtractPrompt（entities+concepts JSON）→ Summary → ChunkCitation
- **dedup 预筛**（wiki_ingest_dedup.go）：pg_trgm+Jaccard 预筛（TopK=5、阈值 0.08）再交 LLM 判合并，配确定性拒绝规则——省 LLM 调用的关键
- Reduce 相：per-slug Redis 锁合并已有页
- wiki_page.go 数据模型：KB 内唯一 Slug、InLinks/OutLinks、SourceRefs、Version 乐观锁、LastEditSource（pipeline/agent/user/revert 四来源）+ revisions 两级保留（机器快照 50/硬顶 200，保护人工编辑）
- 冲突检测=agent 工具（wiki_flag_issue.go：mixed_entities/contradictory_facts/out_of_date+suspected_knowledge_ids）
- 不抄的：Postgres+Redis+asynq+ES 四件套重基建（ApeAdmin 是 SQLite 轻量插件）

### 发现 2：质量闸门范式（swarmvault 候选晋升 + llm_wiki page-merge）
- swarmvault（MIT 可移植）候选晋升量化门槛（candidate-promotion.ts:5-10）：minSources≥3、minConfidence≥0.8、minAgreement(Jaccard)≥0.7、minDegree≥2、minAgeHours≥24、maxPerRun=25——**证据充分才允许转正，量化抑制 LLM 幻觉页面**
- approval bundle 快照（vault.ts:3046）：变更不落 live wiki，写 approvals/compile-<时间戳>/ 快照等人工 review_decision，可整体 apply/回滚
- semanticHash+schema hash 变化 → 全部源标 dirty 强制重编（增量失效判定）
- nashsu/llm_wiki（GPL 只借鉴机制）page-merge 三层保护：①frontmatter 数组字段确定性 union；②body 交 LLM 合并但 **70% 缩水阈值**拒绝疑似截断；③LOCKED 字段强制回写。另：FILE 块输出协议+**路径安全门**（isSafeIngestPath 防 prompt 注入路径逃逸）、内容寻址 review id

### 发现 3：EverOS 的"成本可关"记忆运行时（Apache-2.0）
- Markdown+YAML frontmatter 是唯一真相源，SQLite（审计/队列/LSN）与 LanceDB（向量+BM25）都是**可重建派生层**——删 .index/ 不丢记忆
- 摄入：per-session 缓冲 → 边界检测器 1 次 LLM 切 MemCell → **每细胞恰好 2 次 LLM**（语言判定+episode 提取）→ 其余（atomic facts/profile 聚合/skill 聚合/reflect）全由 OME 离线引擎异步补
- **ome.toml 策略热加载开关（~2s）**：低价值策略整体关停——成本控制的范式答案
- 检索：HYBRID 三路（BM25+episode 向量+atomic-fact MaxSim）→ RRF 融合；RESERVED_FIELDS（owner_id/app_id/project_id）服务端绑定禁客户端覆盖——多租户盖戳范式
- 注意：核心算法在独立 PyPI 库 everalgo（本仓 104 处 import），引依赖需连带评估
- 对 ApeAdmin：抄 buffer+boundary 摄入、episode 粗存+profile 重写双粒度、策略开关、forget_session；砍 LanceDB（SQLite FTS5 起步）、语言判定（中文单语省 1/3 调用）

## 三、联网层与管理后台验证结论

- **vane 三层联网开关（MIT，设计直接映射）**：用户级 sources（默认关）→ LLM 结构化分类 skipSearch（规则：不确定=联网）→ **关闭时工具不挂载**（LLM 根本看不见，比 prompt 禁止更可靠）+ standaloneFollowUp 多轮改写独立化 + 三档 maxIteration（2/6/25）
- **semanticscholar 三家最弱**：无限速器、无礼貌池、tenacity 只重试 ConnectionRefusedError（429 被 raise 成它）、每次新建 AsyncClient；作 collect 工具需外包共享限速器（≥1s）+短重试（≤3 次）+连接复用，包装量 100-200 行
- **llmwiki-suite**（0★ 单人项目）：零依赖核心（pyproject dependencies=[]）+53 测试+CI 四版本矩阵；**索引指纹三向比对**（mtime_ns+size+blake2b，防 git checkout 刷 mtime 假阳性）值得抄进 ApeAdmin 文档库增量索引；成熟度中低不引依赖
- **MaxKB（GPL 只看设计）**：①**位图任务状态**（4 类任务×8 态字符串编码，文档列表一列显示复合进度）；②**应用即 MCP Server**（把平台能力反向暴露为 MCP 工具+Bearer 鉴权）；③MCP 工具保存即校验连通（SandboxMCPBackend）；④Problem-ParagraphMapping 人工问答关联（词条审核数据基础）

## 四、整合后的最终技术决策（两轮 24 仓合并）

### 记忆/习惯画像层
- 主管线：EverOS 的 buffer+boundary 摄入（先攒后切，天然过滤闲聊碎片）+ episode 粗存 + profile 单文件重写
- 提取内核：mem0 式单次 ADD-only + MD5 去重（降级路径，成本敏感时用）
- 画像演化：graphiti 式四时间字段（valid_at/invalid_at/expired_at）SQLite facts 表
- 淘汰：TTL+访问计数+淘汰队列（自研，MindForge 无可抄）+ forget_session 式入口
- 策略开关：ome.toml 式热开关（成本可关）
- 多租户：RESERVED_FIELDS 服务端盖戳 + supermemory namespace 概念
- AI 自编辑：Letta 三原语（append/replace/replace-all）按重要性选层准则
- 全部走后台任务队列（SQLite 单写者，多 worker 串行）

### LLM Wiki 编译层（本批新增，原方案最大的升级）
- 数据模型照 WeKnora：slug 唯一、InLinks/OutLinks、SourceRefs/ChunkRefs、Version 乐观锁、LastEditSource 四来源、revisions 两级保留（机器快照限 50 保护人工编辑）
- 摄入管线照 WeKnora：pending 队列+debounce+批处理 → **pg_trgm/Jaccard 式预筛+确定性拒绝再 LLM 判合并**（SQLite 用 FTS5/trigram 等价替代）
- 写入协议照 nashsu：FILE 块输出协议 + 路径安全门（防注入逃逸）+ page-merge 三层保护（70% 缩水阈值+LOCKED 字段）
- 质量闸门照 swarmvault：候选晋升量化门槛（minSources≥3 等 6 参数）+ approval bundle 快照（变更隔离待审可回滚）+ semantic-hash 增量失效
- 冲突检测：agent 工具标记 issue（mixed_entities/contradictory_facts/out_of_date）+ LLM 语义 lint + 晋升门槛三层组合
- 引用整合：STORM 纯 Python 管线整体移植（上轮结论不变）

### 联网采集层
- 三层开关照 vane：总开关默认关 → LLM 分类 skipSearch → 关闭时工具不挂载；配 standaloneFollowUp 改写 + 三档迭代上限（映射既有 ≤30/≤10 护栏）
- 默认栈不变：httpx（trust_env=False）+ trafilatura 纯函数 + crawl4ai（Apache-2.0）可选增强
- 学术三库：arxiv.py（全局单例+3s 节流后台跑）、pyalex（礼貌池 email+max_retries≥3+线程池）、semanticscholar（外包限速器后才可用）

### 管理后台（Vue3+ElementPlus）
- MaxKB 功能矩阵简化版：知识库列表（type/scope/限额）、文档管理（位图任务状态列+失败重试）、任务中心、设置开关、词条审核（可后置）
- PandaWiki 概念层：草稿→发布三态+RagInfo 同步状态可视化、节点三权限位（answerable/visitable/visible）、**MCP Server 作为知识库出口**（12 出口矩阵含微信/钉钉/飞书渠道）
