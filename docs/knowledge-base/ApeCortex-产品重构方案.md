## 二、目标信息架构（菜单树）

```
ApeCortex（分组名，旧库「AI 知识库」自动改名）
├── 知识中心      ← 新增，第一项：公开知识库阅读器（分类文件夹 + 分类库浏览）
├── 知识空间      ← 重做：空间列表 → 空间详情页（文档管理 + 词条管理两个 Tab）
│                   （独立「词条管理」菜单删除，功能并入）
├── 审核中心      ← 晋升审核升级：词条晋升 / 文档推送 / 违规处置 三队列
├── 任务中心      ← 保留（异步任务可视化，样式统一）
├── 记忆画像      ← 保留
└── 插件设置      ← 保留
```

层级设计核心决策（回应「文档管理和词条的层级设计你自己考虑」）：

```
空间 (KbSpace)
 └── 文档 (KbDocSource)     ← 原始资料：上传/爬取/采集的整篇内容，「料」
      └── 词条 (KbWikiPage) ← 由文档编译拆解产生的知识点，「成品」
```

即 **文档是词条的来源层，词条是文档的知识化结果**。理由：
- 上传文档 → 一键编译 → 产出词条（已有 compiler 管线，`source_refs` 本就记录词条→文档溯源）；
- 词条详情页反查「来自哪个文档」；文档详情页看「拆出哪些词条」；
- 与 MaxKB（文档→分段→问答对）、WeKnora（source→wiki page）的成熟模式一致；
- 推送公开库走**文档级**（用户建议）：公共库侧收文档 → AI 分类 + 拆词条，天然对齐这条链。

## 三、模块设计

### 3.1 品牌统一（N1，小改动）
- seed 增加**存量菜单迁移**：启动时把旧名「AI 知识库」顶级目录更新为 name=ApeCortex（幂等，不动用户自建的子菜单）。
- 侧边栏分组名显示 ApeCortex（i18n `menu.kb.label` 已就绪）。

### 3.2 知识中心（新页面，第一菜单）

**定位**：后台内嵌的公开知识库阅读器（复用 M3 只读出口的数据面）。

**布局**（参考 PandaWiki 阅读侧 + 档案式设计基因）：
```
┌──────────────┬──────────────────────────────────┐
│ 分类导航       │  公开库横幅（名称/描述/词条数/贡献者数）    │
│ ├ 📁 技术教程  │  ──────────────────────────────  │
│ ├ 📁 行业报告  │  搜索 + 词条列表（卡片式，标题/摘要/更新时间）│
│ ├ 📁 产品资料  │  → 点击词条：右侧抽屉或详情页         │
│ └ 未分类      │     渲染 Markdown 正文 + 来源引用      │
│ 分类库直达     │                                    │
└──────────────┴──────────────────────────────────┘
```

**数据模型**：
- 新表 `KbCategory`（id、name、icon、sort、parent_id 支持一级两层；管理员在知识中心内维护）
- `KbSpace` 加 `category_id`（可空 → 「未分类」）
- 公开库列表 = visibility=public 的空间 + 其 category_id 聚合

**两种查看路径**（用户提的「分类文件夹或分类知识库」）：左侧点分类文件夹 → 看该分类下所有库的词条聚合；也可直接点某个分类知识库（公开空间）进库内浏览。均只读，走 live 词条。

### 3.3 知识空间重做（吸收词条管理）

**空间列表页**（现有页面优化）：卡片按「我的 / 共享给我 / 公开」分组保留，卡片视觉升级（品牌色图标、统计、hover 交互），点卡片进**空间详情页**。

**空间详情页**（新路由 `/knowledge-base/spaces/:id`）：
```
┌───────────────────────────────────────────────┐
│ 空间名 [共享/私有]  概要条：文档数·词条数·成员·最近编译     │
├───────────────────────────────────────────────┤
│ Tab1 文档管理   │ Tab2 词条管理   │ Tab3 成员/设置(共享库) │
│ ──────────────  │ ──────────────  │ ─────────────────── │
│ [上传文档][爬虫] │ [搜索][状态筛选]  │  成员表/凭证/自审开关  │
│ 文档列表：       │ 词条列表+详情双栏 │                      │
│  标题/类型/字数/  │ （现 pages 页     │                      │
│  编译状态/词条数/ │  功能整体迁入，   │                      │
│  操作(编译/推送) │  交互重做）      │                      │
└───────────────────────────────────────────────┘
```

- **文档管理 Tab**（参考 MaxKB 位图任务状态列）：
  - 上传：md / txt / 粘贴文本 / URL（现有能力界面化）；PDF/DOCX 解析依赖重，**N3 再评估**（pypdf/python-docx 可选装）
  - 每行：来源类型标签（upload/crawl/web/arxiv）、字数、编译状态（待编译/编译中/已产出 N 词条/失败重试）、操作：重新编译、**推送公开库**、删除
  - 点击文档 → 抽屉查看全文 + 拆出的词条列表（双向溯源）
- **词条管理 Tab**：现 pages/index.vue 的双栏列表-详情整体迁入，去掉顶部「选空间」下拉（空间上下文已在页面参数里）；状态 chip、编辑/发布/晋升操作保留
- **成员/设置 Tab**：成员管理、API 凭证、（共享库）成员表格从 spaces 列表弹窗迁入

### 3.4 公开库推送 + AI 分类 + 违规审核流（N2）

**推送链路**（用户核心诉求 2b + 3 后半）：
```
个人空间文档 → [推送公开库] → 待审队列（审核中心-推送 Tab）
                                   │
                    ┌──────────────┴──────────────┐
                    ▼ 后台任务（复用 KbJob 管线）      │
              ① AI 自主分类：LLM 读文档 → 建议分类       │
                 （从分类树中选最贴切一级/二级）          │
              ② AI 违规初筛：LLM 判风险类型与等级         │
                 （涉政/色情/暴恐/侵权/广告/隐私泄露）     │
              ③ 附拆解预览：建议拆出的词条标题列表         │
                    └──────────────┬──────────────┘
                                   ▼
                    人工审核（审核中心）
                    ├─ 通过 → 文档存档公开库（挂 AI 建议分类，审核员可改）
                    │         → 触发词条编译拆解（compiler 管线，产出公开词条）
                    ├─ 拒绝 → 不入公开库，记录理由（正常内容，走正常退回）
                    └─ 违规 → 不入公开库，转入违规处置队列（内容留存供人工核查，
                              处置动作：删除/标记存证）——「违规的东西不入库留存进行人工处理」
```

**数据模型**：新表 `KbPublicSubmission`
- id、source_space_id、source_doc_id、target_space_id（默认公共总库，审核员可改）
- status: `ai_reviewing / pending(待人审) / approved / rejected / violation / disposed`
- ai_category_id、ai_reason（LLM 分类理由）、ai_risk_type、ai_risk_level（低/中/高）
- split_preview（建议词条标题 JSON）
- reviewer_id、review_comment、reviewed_at、disposal_action（violation 处置：deleted/kept_evidence）
- 一次提交 = 一次后台任务（2~3 次 LLM 调用，受 `daily_job_limit` 约束）

**审核中心**（promotions 页升级）：三 Tab = 词条晋升（现有）/ 文档推送（新）/ 违规处置（新）。违规队列只展示 AI 判违规的提交，不混入正常推送。

**成本控制**：AI 分析在推送时触发一次，审核通过后编译词条复用现有编译任务；同文档重复推送（content_hash 相同且未处置完）拒绝。

### 3.5 AI 全能助手集成（N3）

**聊天页配置区**（截图红色框位置，输入卡片左侧与「工具」开关同排或收纳进设置弹窗）：
- **知识库召回范围**：不启用 / 挂载某个我的空间 / 公开库（三选一或自定义组合）→ 影响聊天中 kb_query 的默认召回通道与空间上下文
- **记忆召回开关**：是否在对话中自动注入我的记忆条目与画像（关 = 只有用 kb_query 工具时才用）
- 持久化：复用现有 chat 会话偏好机制（provider/model 同款存法），插件侧存用户级默认值（KbUserSetting 或复用 settings JSON）

**技术要点**：聊天页加一个「知识库」配置弹窗/下拉（读插件 API 拿我的空间列表）；偏好变化写插件表；kb_query 工具实现里读当前用户偏好作为默认空间/通道。

### 3.6 爬虫 MCP 工具 kb_crawl_site（N3）

**场景**：用户在全能助手里说「帮我爬 https://example.com/docs 这个站，存到我的知识库」→ AI 调用 `kb_crawl_site` → 多页采集 → 形成知识文档 → 存个人空间（KbDocSource, source_type=crawl）→ 可继续编译词条。

**引擎选型**（按既有调研结论）：
- **默认轻量栈（零新增重依赖）**：httpx（`trust_env=False`，显式代理可配）+ trafilatura 纯函数抽取 + 同域链接发现
  - 合规：遵守 robots.txt、同域限制、深度上限（默认 2）、总页数上限（默认 30）、单页超时、`daily_job_limit` 日限额
  - 产物：每页抽取正文，聚合为一份 Markdown 知识文档（带来源 URL 清单），或分页存多份文档（参数控制）
- **可选增强**：crawl4ai（Apache-2.0 已确认可依赖）——JS 渲染站点时装 playwright 后启用；v1 先做轻量栈，crawl4ai 作为后续增强开关
- 界面入口：知识空间详情页「爬虫」按钮（表单：URL/深度/页数/存到哪个空间）+ 聊天 MCP 工具双入口

## 六、已拍板决策（2026-11-25 用户确认）

- **D1 知识中心浏览形态：两种视图可切换**——顶部 Tab「按分类 / 按知识库」，两种都做
- **D2 违规处置：留存待人工处置**——违规文档不进公开库，内容与 AI 判定依据留在违规队列，管理员处置（删除/存证）后才清理
- **D3 爬虫引擎：直接上 crawl4ai**（Apache-2.0）——需安装 playwright 重依赖，JS 渲染站点可爬；安装失败时降级 httpx+trafilatura 轻量路径
- **D4 文档格式：含 PDF/DOCX 一步到位**——pypdf + python-docx 依赖加入，md/txt/URL/粘贴/上传四路齐开
- **D5 聊天页配置：召回范围 + 记忆开关 + 自动注入**——增加「自动注入」项，开启后每轮对话自动把相关记忆/知识片段注入上下文（token 成本更高，用户自选）
