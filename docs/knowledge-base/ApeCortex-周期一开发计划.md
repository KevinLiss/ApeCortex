## 二、里程碑

### M1 · 质量与信任（D1–D3）

**目标**：消除"说错话 / 记错事 / 报原始错误"三类信任损伤。

**交付物**
1. **检索相关性下限**
   - `search_all` 引入最低相关度阈值（字符级相似度 + FTS rank 归一化），低于阈值不入结果集
   - 结果项增加 `relevance` 与 `low_relevance` 标记，`kb_query` 输出明确区分"命中"与"无命中"
   - 兜底逻辑改为"宁缺毋滥"：公开库只有无关条目时不返回
2. **记忆提取边界**
   - 提取 prompt 显式排除：系统状态、工具报错、权限提示、一次性操作指令、对 AI 的元指令
   - 增加确定性后置过滤（关键词黑名单 + 类型校验 + 自指检测），命中直接丢弃并记录原因
   - 正反例测试 ≥8 条（含本次实测中的"缺少 kb_query 权限"误沉淀）
3. **错误可读化与区块降级**
   - 统一前端错误映射：404 → "接口不存在，可能后端未更新"、403 → "权限不足，请联系管理员"、网络 → "服务未启动或端口不通"
   - 页面区块独立容错：贡献榜/任务列表失败不阻断审核列表与词条详情
4. **可观测**
   - 知识库路由统一异常日志（trace id + 路由 + 用户 + 耗时）

**验收标准**
- 20 条人工评测集（含 5 条不相关 query）：兜底垃圾返回 = 0
- L2 用例全部不落库，且日志可见丢弃原因
- 模拟后端未更新：页面出现可读提示而非 `Request failed with status code 404`

### M2 · ApeCortex 品牌与分发（D4–D6）

**目标**：任何人按文档 15 分钟装起来并跑通主路径。

**交付物**
1. **品牌统一**
   - 中英 README、`plugin.json`（display_name = ApeCortex）、菜单分组名、i18n 文案、插件管理卡片描述
   - 品牌定位一句话：给 ApeAdmin 装上知识大脑皮层
2. **安装与升级文档**（`docs/knowledge-base/安装与升级.md`）
   - 依赖与可选 extras（`knowledge-render`）
   - **权限清单**：角色需同时具备知识库 16 个权限点 + `mcp:tools:call`（宿主 MCP 总开关）
   - 联网开关与数据外发合规说明、学术源免开关说明
   - 升级 / 回滚步骤、`_backups` 说明
   - 故障排查：404（后端未更新）、403（权限）、端口不通、渲染通道未装
3. **分发包 0.3.0**
   - 按已验证结构（zip 根 `plugin.json` + `knowledge_base/`）打包
   - 热升级验证：0.2.0 → 0.3.0 数据/菜单/权限零丢失
   - `APP_VERSION` → 2.12.0

**验收标准**
- 干净环境（新库）按文档装机，P0→P3 主路径全通
- 升级后词条 / 晋升 / 记忆数量与升级前一致，菜单与权限点自动补齐

### M3 · 协作能力（D7–D10）

**目标**：从"个人知识库 + 公共库"扩到"团队共享库"，并对外提供只读出口。

**交付物**
1. **shared 空间 ACL**
   - 新表 `kb_space_member(space_id, user_id, role: reader|writer)`
   - `visibility` 增加 `shared`；SQL 层成员校验（与现有双通道同一纪律，禁止 if 判断兜底）
   - 成员管理 UI（邀请 / 移除 / 角色），空间卡片显示成员数
   - 召回扩为三通道：私有（owner 硬过滤）→ 共享（成员校验）→ 公开（live-only）
2. **公开库只读 MCP 出口**
   - 独立只读凭证（不复用管理员 token），仅可访问 `live` 公开词条
   - 新工具 `kb_public_search`（无写能力），限流 10 次/分钟，全量审计
   - 限制：不含 draft/archived、不含任何私有/共享内容
3. **晋升流程增强**
   - 批准后进入"待发布"队列，公开库 owner 在晋升页看到红点与列表
   - 自审策略可配置（默认禁止，`kb_setting.promote_allow_self_review=false`）
   - 审核意见模板（短理由快捷选项）

**验收标准**
- A 建共享库，B 只读、C 可写；非成员访问 403；召回不越权（三组用例）
- 外部 AI 只能读 live；尝试 draft / 私库 ID → 403 且审计留痕
- 批准后 owner 侧 30 秒内出现待发布提示

---

### M4 · 检索与运营（D11–D13）

**目标**：召回质量从"能用"到"好用"，公开库具备运营能力。

**交付物**
1. **混合检索**
   - FTS + 语义向量 → RRF 融合；embedding 方案见"待决策 D1"
   - 检索结果统一打分并在 UI 显示相关度
   - 评测集（30 条 query）对比 M1 基线，Top5 相关性目标 ≥85%
2. **记忆治理**
   - 同主体冲突检测：新旧事实并存时旧事实自动 `invalid_at`
   - 近似记忆合并（阈值可调），避免重复条目
   - 画像重写预算（token / 次数上限），成本可观测
3. **公开库运营**
   - 审核队列排序（提交时间 / 来源数 / 置信度）
   - 快照 vs 现版 diff 视图（新增 / 修改 / 冲突三态着色）
   - 词条下线与举报入口
   - 贡献榜周期榜（本周 / 本月 / 全部）

**验收标准**
- Top5 相关性 ≥85%，且不相关 query 仍为 0
- 冲突记忆不产生双事实；画像重写 token 有上限且可查
- 运营页可完成"审 → diff → 发布 → 下线"闭环

---

### M5 · 硬化与发布（D14–D15）

**目标**：可对外发布。

**交付物**
1. 宿主 `import_plugin` 的 `has_root` 修复合回主仓库 + 单测（`single != plugin_name` 判定）
2. 审计全覆盖：MCP 调用、公开库写入、只读出口访问
3. 成本护栏：LLM 每日预算、任务并发上限、熔断阈值
4. 发布 `v2.12.0`：tag、分发包、Release notes、升级说明

**验收标准**
- 后端全量测试 ≥90 passed；前端 `vue-tsc` + build 通过
- 干净环境安装 + 升级双路径成功
- 预算/限流/审计各有一条实测证据

## 四、待决策（开工前需你拍板）

**D1 · embedding 方案**（M4 阻塞项）
- 方案 A：API embedding（复用已配供应商，零本地依赖；有调用成本与数据外发）
- 方案 B：本地 ONNX 小模型（`bge-small-zh`，约 100MB；不违反"禁入 torch/sentence-transformers"纪律，但引入模型文件分发）
- 方案 C：仅优化 FTS（jieba 分词 + 同义词表 + 字段权重），零新依赖
- 建议：先 C 打底 + A 作为可选增强（可关闭），把 B 列为后续

**D2 · 表结构变更**（M3 阻塞项）
- 新增 `kb_space_member` 与 `visibility` 枚举扩展，需要对 P0/P1 已装库做幂等迁移
- 建议：沿用现有 schema 自查迁移机制（插件启动时对比建表），不引入 Alembic 依赖

**D3 · 公开库出口鉴权**（M3 阻塞项）
- 复用宿主 MCP ticket（省事，但 ticket 生命周期与权限粒度偏管理端）
- 新建只读 API key（独立表 + 限流 + 审计，粒度更干净）
- 建议：新建只读 API key，默认关闭，按需开启
